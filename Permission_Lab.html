Station T · Day 1

Meet the terminal

If you've never used a terminal, you're in the right place. By the end of today you'll be able to find out who you are, where you are, what's around you, how to move between folders, and how to become a different user.

What is a terminal?

Most of the time you use a computer by clicking: icons, folders, menus. That's called a graphical interface. A terminal is a different way to control the same computer: you type an instruction (a command), press Enter, and the computer types back an answer. No mouse, no icons. The program reading your commands is called the shell; on most Linux computers it's called bash.

Everything you can click on, you can also do by typing. Here's how things you already know line up with terminal commands:

Why cybersecurity people live in the terminal

  • Most servers on the internet run Linux, and most have no screen or mouse. The terminal is the only way in.
  • One typed command can check or fix permissions on thousands of files at once.
  • Most security tools are terminal programs.
  • The AP exam expects you to read and write these commands.

How to type in the practice terminals

  1. Click inside the black box. A blinking bar (the cursor) shows where your typing goes.
  2. Type the command exactly, including spaces.
  3. Press Enter. Nothing happens until you do.
  4. Read the answer. It prints right under your command. Then a fresh prompt appears for the next one.
Getting an error is normal. Professionals see errors all day. They mean "I didn't understand that" or "you're not allowed," never "you broke something." Nothing you type here can damage a real computer.
  • command not found → check spelling and capitals, then retype. Press ↑ to bring back what you typed and fix it.
  • No such file or directory → the name is wrong. Type ls to see the real names.
  • Permission denied → you typed it right, but the person you are isn't allowed. That's what this whole lab is about.
  • Lost? whoami tells you who you are. pwd tells you where you are.

Read the prompt

Before you type anything, the terminal shows a prompt. It's not decoration. It tells you who you are and where you are, and it updates every time those change.

mayawho you are @"at" cyberlabcomputer name : ~/labfolder you're in $regular user

Read it as "Maya, at the computer named cyberlab, in the lab folder." If the last character is # instead of $, you're logged in as root, the all-powerful administrator.

How a command is built

lscommand (the verb)-loption (how to do it)report.txtargument (what to do it to)
  • Spaces matter: ls -l works, ls-l doesn't.
  • Capitals matter: Notes.txt and notes.txt are different, and LS isn't a command.
  • Options start with a dash. Some commands need an argument (cat needs to know which file); some don't (whoami).

Why would we switch users?

Security testers don't just read the permission settings and hope they're right. They try the door from the outside. Switching users lets you sit in Sam's seat and see exactly what Sam can and can't do. That's how you prove a file is really protected.

Station P · Day 2

See permissions in the terminal

In Station T, Part 3, Sam got "Permission denied" trying to enter robotics. Now you'll find out why. Add -l (long) to ls and every file shows its permissions.

CED 5.2.D.4 To view the current permission settings for a file, use the command ls -l, which will show the current settings for the default entities.
Who's who refresher. maya owns the lab files and is in group lab. leo is in group lab. sam is not in lab, so for Maya's files he's "others." root can do anything. Not sure who you are in a terminal? Type whoami; to see your groups, id.

Parts of an ls -l line

-rw-r-----permissions 1links (ignore) mayaowner labgroup 2048size (bytes) Oct 30 14:02last changed report.txtname

Three kinds of access, always in the order r w x

LetterNameOn a file…On a folder…
rreadview what's inside (cat)list what's in it (ls)
wwritechange itadd or delete files in it
xexecuterun it as a program (./scanner)enter it (cd)

A dash - means that permission is missing. r-x means read and execute, but no write.

Three groups of people, always in the order owner, group, others

The very first character is the type: - for a file, d for a directory. Then nine letters in three chunks.

-rw-r-----
typeowner (maya)group (lab)others (everyone else)
CED 5.2.D.2–3 Read, write, execute are abbreviated rwx; a - means that permission is absent. Permissions are set for the file owner, the file group, and all other users, always in that order, displayed with no spaces (e.g., rwxrwxrwx).

The two-step check

Step 1: find your chunk. Are you the owner? Use the first chunk. If not, are you in the file's group? Use the middle chunk. Neither? Use the last chunk. You only ever get one chunk. (That's why id matters: it tells you your groups.)

Step 2: read it. Each letter that's there is something you can do.

Practice the check: pick a file, then a person

Try it: predict, then test

For each step, predict first (will it work?), then run it and see. Record results on your sheet (P2–P7).

What's that + at the end?

budget.xlsx shows -rw-r-----+. The + means someone gave extra permissions to a specific person beyond the normal three chunks. ls -l won't tell you who. getfacl (get file access control list) will. That's why Sam could read it in the last step even though he's "others."

CED 5.2.D.4 If there is a + symbol at the end of the permissions, other permissions have been set for that file and they can be viewed with the getfacl command.

Connect it: permissions are bits

Each chunk is three switches: r, w, x. On = 1, off = 0. Three bits make 0 through 7, which is exactly one octal digit. So the nine letters you saw in ls -l become three octal digits.

r = 4, w = 2, x = 1 are just binary place values

Station E · Day 4

Change permissions with numbers

chmod means "change mode." The numeric method sets all three chunks at once.

chmod 750 test

First digit = owner, second = group, third = others. The command above gives the owner read, write, and execute; the group read and execute; and everyone else nothing.

CED 5.2.D.5–6 To modify permission settings use chmod, with the numeric or symbolic method. Numeric syntax is chmod ### filename. Examples: chmod 750 test; chmod 543 test (owner read and execute, group read only, others write and execute); chmod 777 test (everyone gets everything).

Common patterns

NumberLettersTypical use
600rw-------Private file. Only the owner can see it.
640rw-r-----Owner edits, team reads, outsiders blocked.
644rw-r--r--Public file anyone can read, like a web page.
750rwxr-x---Program or folder the team can use.
755rwxr-xr-xProgram anyone can run.
777rwxrwxrwxAlmost always a mistake. Anyone can change it or replace it with something harmful.

Who is allowed to run chmod?

Only the file's owner or root. Leo is in the group, but that doesn't let him change permissions. This is discretionary access control (DAC): the owner decides.

Watch it first

Try it: lock it down and test it

Now you do it. The habit to build: check → change → check again → test as someone else.
